## What this package is

A working floor-plan-to-photoreal-room-render pipeline, covering two
distinct cases:

1. **Two authored, source-grounded units** - Residence A (1428 Brickell) and
   Continuum Tower Residence 01 - with hand-built layout graphs, doorway
   adjacency and minimap data that can't be auto-derived to tour quality.
2. **Any other floor plan a viewer uploads** - room boundaries, walls,
   openings and dimensions are extracted by a deterministic computer-vision
   pipeline (`backend/app/plan_detect.py`: preprocessing → scale calibration
   → wall detection → room segmentation → opening detection). This works
   with no API key at all, and never invents a room or a dimension it
   couldn't actually measure - an unmeasured room is reported honestly
   (`dimension_source: "not_available"`), never given a fabricated size.
   Passing `total_interior_sqft` at upload time (the one number a real
   listing almost always already has - see `backend/API.md`) gives the
   pipeline a real scale reference so it can report actual measurements
   instead of "not available" for a plan with no OCR-legible printed
   dimension text, which is most real-world listing floor plans.

## Going live with real generation

Set `OPENAI_API_KEY` in the deployment environment - nothing else. The API
automatically switches from the mock renderer to the real OpenAI provider
the moment a key is present (`backend/app/config.py::resolve_provider`); you
do not need to also set `LUXE_PROVIDER=openai` by hand. See
`backend/.env.example` for every recognized environment variable (names
only - no secret values are stored anywhere in this repository).

## Important scope notes

- The Continuum input supplied for reconstruction is a screenshot, not a
  CAD file. Its room regions are source-grounded and source-shaped, but
  exact CAD/survey-level wall and opening coordinates are not claimed for
  that specific plan.
- Automatic room segmentation on a visually complex/ornate plan (like the
  supplied Continuum screenshot) can currently over-segment relative to the
  "intended" room count - geometry and dimensions stay honest either way,
  but perfect room-count accuracy on complex real-world plans without a
  printed room-count reference is a known, disclosed limitation.
- Generated images are still-image room views, not true 360-degree
  equirectangular panoramas. They're exposed through `panorama_url` for
  compatibility with the existing viewer.

## Updated API contract

The backend includes a versioned `/api/v1` integration surface for project
creation, floor-plan uploads, queued jobs, status polling, structured
geometry, rooms, assets, manifest retrieval and viewer access, plus legacy
`/units`/`/jobs` routes for the two authored demo units. API-key
authentication, idempotency keys, durable SQLite job metadata and optional
webhooks are included. See `backend/API.md` for the complete reference.
